安装本地识别服务

需要系统装有 Python 3。插件本身各平台通用，只有这个本地服务的安装方式分系统。

一条命令，不用 clone 仓库——脚本会在当前位置建一个 happysubs-server 文件夹，装好 Python 环境，并从 sherpa-onnx 项目自己的 release 下载模型（约 500MB 压缩包，解压后保留 193MB）。

curl -fsSL https://raw.githubusercontent.com/huanshuowang/happysubs/main/setup.sh | bash

这条只跑一次。跑完它会打印出你以后每次要用的那一条命令，也就是下面这个。

以后每次——启动它，看视频期间让它一直开着：

~/happysubs-server/start.sh

这个路径假设你是在主目录下安装的；装在别处就换成那个位置——安装结束时脚本会打印完整的那一行。忘了装在哪：find ~ -maxdepth 4 -name start.sh -path '*happysubs-server*' 能找出来。这个脚本在任何目录下运行都行，不需要先 cd。

端口被占用时执行 lsof -ti:8765 | xargs kill 再重启。已经 clone 了整个仓库的话，在仓库根目录跑 ./setup.sh 效果一样。

Windows 上没有现成的脚本，下面三步做的是和 macOS 那个脚本一样的事。

  1. 到 python.org 下载 Windows 安装包，安装时记得勾上 Add python.exe to PATH。

  2. 打开 PowerShell（开始菜单搜 PowerShell），把下面整段一起粘进去回车。它会在当前目录建一个 happysubs-server 文件夹，装好 Python 环境，并下载 4 个模型文件——约 190MB，不用解压。

    # Without this, PowerShell's progress bar makes large downloads roughly ten times slower.
$ProgressPreference = "SilentlyContinue"

mkdir happysubs-server -Force | Out-Null; cd happysubs-server
$repo = "https://raw.githubusercontent.com/huanshuowang/happysubs/main/server"
iwr "$repo/server.py" -OutFile server.py
iwr "$repo/requirements.txt" -OutFile requirements.txt

py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# The model, straight from the sherpa-onnx author's own Hugging Face repo.
mkdir model -Force | Out-Null; cd model
$hf = "https://huggingface.co/csukuangfj/sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20/resolve/main"
foreach ($f in "tokens.txt", "encoder-epoch-99-avg-1.int8.onnx",
               "decoder-epoch-99-avg-1.int8.onnx", "joiner-epoch-99-avg-1.int8.onnx") {
  iwr "$hf/$f" -OutFile $f
}
cd ..

# A launcher to double-click from now on, so there is nothing to retype later.
iwr "$repo/start.bat" -OutFile start.bat

  3. 以后每次——双击 happysubs-server 文件夹里的 start.bat，看视频期间让那个黑窗口开着就行，不用输任何命令。

    想用命令行的话，在那个文件夹里跑这条一样：

    .\.venv\Scripts\python.exe server.py

Windows 上几点：py -3 提示找不到的话改用 python——从微软商店装的 Python 不带 py 启动器。端口被占用时用 netstat -ano | findstr :8765 查到 PID，再 taskkill /PID <PID> /F。如果访问 huggingface.co 不通，把上面那段里的 huggingface.co 换成 hf-mirror.com 即可，路径完全一样。

看到 监听 ws://127.0.0.1:8765 就绪。然后在插件弹窗切到「实时听译」标签，点开启。

几点注意：先点一下视频播放，浏览器要求有用户交互才允许处理音频。服务端一次只服务一个页面，同时开多个标签页会互相干扰。模型和 Python 环境都在那个文件夹里，换机器重跑一次安装即可。

更新日志

2.1.0 — 双语合成一条字幕

一条字幕，两种语言。以前译文是另画一行贴在播放器字幕下面，两行各长各样，还常常挤在一起。现在两行一起出现、一起换，一句一次。自动生成字幕不再滚动出现文字，换成整理好的整句。想让所有视频都这样，打开「所有视频都由插件画双语」即可。

外观归你调，原文译文可以不一样。字号、颜色、背景透明度，原文和译文各调各的，也能一个开关锁成同一套；调乱了一键恢复默认。圆角底板贴合文字、文字带柔和阴影，两行紧挨着又不重叠。

字幕可下载。导出成 .srt 格式。可选双语、仅原文、或仅译文。文件名包含视频名、频道名和语言。

一个快捷键开关字幕。Mac 上 ⌘⇧S，Windows / Linux 上 Alt+Shift+S，不用打开弹窗就能在原文和双语字幕之间随时切换。

优化界面。从一整页纯白的系统控件，到更有设计感的软件页面，并更新了 logo。

设置分了主次。常用的留在弹窗首页：开关、字幕样式、第二语言、翻译源、导出字幕。右上角的齿轮进去，是字幕外观和面板语言。原来那个要另开一个标签页的设置页，取消了。

AI 翻译可以选模型，也能自己填。选了 Claude / OpenAI / Gemini / DeepSeek 之后，还能挑具体用哪个型号，自己在速度和质量之间取舍。列表只是几个常用的——选「自定义…」，任何该服务支持的模型名都能直接填进去，不用等插件更新。

AI 翻译的进度，在视频上方看得见。长视频第一句换掉之前要等十几秒，以前这段时间屏幕上什么都没有，看着就像坏了。现在视频上方会显示一行：正在用哪个翻译、已经翻到第几条。翻译失败、或者没填 API Key，也在同一个地方说出来，而不是让你干等。

付费 API 怎么用，你定一次就好。三选一：每个视频都问你（新的默认）、所有视频都直接用它、或者不点按钮就绝不调用。以前只有「问」和「不问」两种，而且默认是不问——填好的 Key 可能一次都不会被提起。

修复。开头有贴片广告的视频不再整段没有字幕；第一句不再压在后面两句上面；广播字幕里表示换人说话的「>>」不再被当成正文翻进译文；看完一个视频，YouTube 自己的自动翻译也不会被留在开着的状态。

2.0.1 — 长视频后半段不再只剩原文

看长视频时，免费翻译经常在中途被悄悄限流，后半段字幕就只剩原文，而且什么提示也没有。现在翻译走更稳的通道、被限流时自己放慢而不是直接断掉；真的翻不出来，也会在字幕上直接说一声。

常见问题

为什么 YouTube 必须开 CC，Vimeo 却不用？

YouTube 上扩展是靠拦截播放器自己去拿字幕的请求，而 YouTube 只在你开 CC 的时候才发这个请求。Vimeo 则是把字幕轨当普通文件放出来，扩展可以自己去读，所以不需要先开任何东西。如果你只想看译文，在插件弹窗里打开 仅显示翻译字幕，关着 CC 也会单独显示第二语言。

B 站需要装什么吗？

不需要。B 站的字幕轨跟其他平台一样直接读取。本地服务只跟实时听译有关，而实时听译只用于完全没有字幕轨的视频。

B 站上提示这个视频没有字幕，是真的吗？

多半是。B 站只对**登录用户**返回字幕列表，所以先确认你登录了。如果已经登录、扩展仍然找不到，那就是真的没有——这正是实时听译存在的理由。

如果视频没有字幕怎么办？

YouTube 和 Vimeo 上大部分视频有自动生成字幕。B 站上大部分**没有**，这正是实时听译的用武之地——它直接听音频，自己把字幕写出来。

翻译准确吗？

默认优先使用视频自带字幕或 Google 免费翻译。如果你需要更高质量，可以手动为当前视频启用 Claude / OpenAI / Gemini / DeepSeek。

会上传我的数据吗？

扩展代码完全开源可审。它只读取当前视频字幕，并只把字幕文本发送到你选择的翻译源。付费 API 只有在明确确认后才会调用。
